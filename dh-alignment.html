Rec #1

Flip the content background to white — DH is not a dark-mode siteBreaking

This is the single most fundamental difference. Dark Horse's content area is white. The dark feeling comes from its pure-black navbar and full-bleed hero images — not from a dark page background. Diablaq currently runs --color-bg: #000 on the body. Comic covers are designed in print — strong black outlines, high contrast — and they pop against white, not against black. Switching to light content with a black nav is the core aesthetic shift that connects you to DH.

Rec #2

Add Oswald for hero and section display headingsQuick win

Dark Horse uses two typefaces, not one: Oswald for big display moments (hero h1, section h2, feature titles) and Roboto Condensed for labels, nav, and card text. Diablaq currently uses Roboto Condensed for everything — and doesn't even load it yet. Oswald is wider, bolder, and more cinematic than Roboto Condensed at large sizes. It's what makes DH's section headers read as authoritative. Both are free Apache 2.0 / OFL fonts.

↗ Dark Horse — fonts.css
/* Both fonts self-hosted as TTF */
@font-face {
  font-family: "Oswald";
  font-style: normal;
  font-weight: 100 900;
  font-display: swap;
  src: url("/static/…/Oswald-Variable.ttf")
       format("truetype");
}
@font-face {
  font-family: "Roboto Condensed";
  font-weight: 100 900;
  font-display: swap;
  src: url("/static/…/RobotoCondensed.ttf")
       format("truetype");
}
/* h1/h2 → Oswald
   nav/h3/labels → Roboto Condensed */
✓ Recommended — diablaq fonts.css
/* Via Google Fonts — Apache 2.0 / OFL */
@import url('https://fonts.googleapis.com/css2?
  family=Oswald:wght@400;500;600;700
  &family=Roboto+Condensed:wght@400;
  600;700&display=swap');

:root {
  --diablaq-font-display: "Oswald", sans-serif;
  --diablaq-font-heading: "Roboto Condensed", sans-serif;
}

/* h1, h2 → display font (Oswald) */
h1, h2 { font-family: var(--diablaq-font-display); }
/* h3–h6, nav, cards → Roboto Cond. */
h3, h4, nav { font-family: var(--diablaq-font-heading); }

Rec #3

Replace the empty hero with a full-bleed featured-releases carouselHigh impact

Dark Horse's homepage opens with a viewport-width Bootstrap carousel showing featured releases — large artwork, the book title in Oswald uppercase over a dark overlay, and a subtitle describing the story. This is the pattern Diablaq's designer was inspired by. Currently Diablaq shows two lines of text. The cover images already exist in the SSG pipeline. The builder just needs to select 3–5 featured editions and pass them to the template.

↗ Dark Horse — carousel structure
<div class="carousel slide"
     data-bs-ride="carousel">
  <div class="carousel-inner">
    <div class="carousel-item active">
      <div class="carousel-item-container">
        <!-- Full-width artwork image -->
        <img src="…" style="width:100%">
        <div class="subtitle">
          <h1>Magic the Gathering</h1>
          <p>Delve into an untold story of
          Jace Beleren…</p>
        </div></div></div>
  </div>  <!-- more .carousel-item -->
</div>
✓ Recommended — home.html hero
{# builder passes featured_editions:
   3–5 editions with featured_image #}
<section class="home-hero">
  {% for e in featured_editions %}
  <div class="home-hero__slide
    {% if loop.first %}is-active{% endif %}">
    <img src="{{ e.cover_image }}"
         alt="" aria-hidden="true">
    <div class="home-hero__caption">
      <h1>{{ e.title }}</h1>
      <p>{{ e.summary }}</p>
      <a href="{{ e.url }}">Czytaj więcej</a>
    </div>
  </div>
  {% endfor %}
</section>
Implementation notes — No JS framework needed: pure CSS carousel with scroll-snap works without Bootstrap. Mark editions as featured: true in their YAML front-matter. The builder filters them and passes the list to the home template. Minimum viable version: a single full-bleed image with a dark gradient overlay and the title in Oswald. No auto-rotation needed — a static hero beats two lines of text every time.

Rec #4

Add a sticky category sub-nav below the heroMedium effort

Immediately below the hero, Dark Horse renders a second sticky navbar with section links: Comics, Manga, Products, Dark Horse Direct… It uses position: sticky; top: 0 and pure black background. This gives users persistent quick access to the catalogue categories and doubles as a visual break between the hero and the content grid. Diablaq's equivalent would be: Publikacje, Zapowiedzi, Nowości, Dobre Licho, Mecenat, Studio. This matches Diablaq's existing nav content — it's a second level of it.

↗ Dark Horse — sticky subnav CSS
.middle-nav-sticky {
  position: sticky;
  top: 0;
  z-index: 99;
  --sticky-navbar-height: 44px;
}

#main-nav {
  height: var(--sticky-navbar-height);
  background-color: black;
}

#main-nav .nav-link {
  font-family: var(--dh-label-font-family);
  font-size: 15px;
  color: #fff;
  text-transform: uppercase;
  font-weight: 700;
}

{# After .site-header, before main #}

/* CSS */
.cat-nav {

Note — On the homepage this nav appears below the hero and sticks as you scroll into the catalogue sections. On interior pages (listing, section pages) it can appear directly below the topbar header, acting as breadcrumb-level context. Hide it on blog/people pages where it doesn't add value by adding a {% if show_cat_nav %} flag to the template context.

Rec #5

Remove border-radius from covers — use hard 1px black edgesQuick win

Dark Horse puts border: 1px solid black and border-radius: 0 on every product cover image. This is intentional: it mirrors how physical comics look — a printed rectangle with a precise edge. Rounded corners feel like a mobile app widget. Diablaq currently uses Pico's default --pico-border-radius on all cover images. Switching to hard corners is a single CSS change that immediately shifts the aesthetic from "generic website" to "editorial publisher."

↗ Dark Horse — product cover CSS
.product-grid .product-result
  .product-img img {
  width: 100%;
  height: 100%;
  object-fit: cover;
  border: 1px solid black;
  /* no border-radius — hard edge */
}

.product-thumb {
  height: 150px;
  width: 100px;
  object-fit: cover;
  /* no border-radius */
}
✓ Recommended — diablaq.css
/* Replace across all cover image rules */
.edition-tile__cover img,
.edition-card__media img,
.project-card__cover img,
.blog-post__cover img,
.edition-details__cover img {
  border-radius: 0; /* was: var(--pico-border-radius) */
  border: 1px solid rgba(0, 0, 0, 0.15);
  /* on light bg: barely visible separator
     on dark bg: increase to solid #000 */
}

/* Keep rounded corners on UI elements
   (blog tags, buttons) — just not covers */
.blog-tag { border-radius: 999px; }
Current — rounded corners
Recommended — hard edges
DH Source — .product-grid .product-result .product-img img { border: 1px solid black } and .product-detail-body .product-cover-col .product-img { border: 1px solid #000000 } — consistent across all product views. Zero border-radius on any comic cover.

Rec #6

Tighten card typography — smaller, denser, Roboto Condensed boldQuick win

Dark Horse product card titles use Roboto Condensed, bold, 12px, uppercase, black. This high-density style is deliberate — it keeps focus on the cover art, not the label. Diablaq's .edition-tile__title is 1rem (~16px) in the default body font. The DH approach fits more comics per row without feeling crowded because the typography itself is compressed. On a light background, black text at 12px bold is crisp and legible.

↗ Dark Horse — product card CSS
.product-grid a {
  text-decoration: none;
  color: black;
  font-weight: bold;
}

.product-grid .product-result {
  width: 116px;
  font-size: 12px;
  font-weight: bold;
  padding-bottom: 0.5rem;
}

/* On hover: underline only.
   No scale, no shadow, no transform. */
.product-grid a:hover {
  text-decoration: underline;
}
✓ Recommended — edition tile
.edition-tile__title,
.project-card__title {
  font-family: var(--diablaq-font-heading);
  font-size: 0.8rem;   /* was: 1rem */
  font-weight: 700;
  text-transform: uppercase;
  letter-spacing: 0.02em;
  margin: 0.4rem 0 0.2rem;  /* tighter */
  color: var(--color-text);
}

.edition-tile__title a:hover,
.project-card__title a:hover {
  text-decoration: underline;
  text-underline-offset: 0.15em;
}

.edition-tile__meta {
  font-size: 0.7rem;
  color: #6c757d;  /* DH: #A9A9A9 */
}
Context — This recommendation assumes Rec #1 (light background) is adopted. On a dark background, 12px black bold text would have terrible contrast. If keeping a dark background, size should stay at 0.85–0.9rem with lighter text. DH's card density pattern is tightly coupled to its white content area.

Rec #7

Switch the topbar from brand red to pure blackHigh impact

Dark Horse's primary navbar is pure black (#000000), not brand red. The brand red (#ba2d00) appears only on CTA buttons, hover states, and accents. Diablaq's current topbar is brand red — which is loud. Black navbar creates a neutral, authoritative frame that lets the cover art do the visual work. The brand red then becomes a meaningful signal ("click here") rather than ambient noise. This is the DH hierarchy: black = structure, red = action.

#main-nav {

  height: 44px;
}

#main-nav .nav-link {

  text-transform: uppercase;
  font-size: 15px;
}

/* Brand red only on:
   - btn-primary buttons
   - hover accents
   - logo background strip
   NOT on the nav itself */

Rec #9

Narrow the content container from 1080px to 960pxQuick win

Dark Horse explicitly overrides Bootstrap's container to 960px maximum width. Diablaq is currently set to --diablaq-content-max: 1080px. At 1080px, text lines are too long and the cover grid feels sparse on wide screens. 960px is narrower, which forces tighter grid density, shorter line lengths in body text (~75ch at typical font sizes), and a more focused layout. It's also the natural width of comic art (which tends to be formatted at ~6.75 inches = ~972px at 144dpi).

↗ Dark Horse — container override
/* Bootstrap max-width override */
.container {
  max-width: 960px;
}

/* Homepage: zero gutter for
   flush full-width sections */
body.homepage .row {
  --bs-gutter-x: 0;
}

body.homepage #content .container {
  padding: 0;
}
✓ Recommended — diablaq.css
:root {
  --diablaq-content-max: 960px;
  /* was: 1080px */
}

/* Homepage sections go edge-to-edge
   (hero, category nav, featured strips) */
.home-hero,
.cat-nav {
  max-width: 100vw;
  margin-inline: calc(-1 * var(--pico-spacing));
}

/* Content grids: use the 960px container */
main.container {
  max-width: var(--diablaq-content-max);
}
Why this matters for the cover grid

At 960px with gap: 1rem, a 4-column edition grid gives each cover ~228px width — well proportioned for comic covers. At 1080px the same grid gives 265px which starts to feel oversized for dense listings. DH's product cards are only 116px wide, allowing 6–8 per row — very information-dense. Diablaq doesn't need to go that small, but 4 columns at 960px matches the DH aesthetic density.

Summary

Implementation roadmap

Ordered by effort and dependency. Recs 2, 5, 7, 8, 9 are isolated CSS changes — do them in one PR. Rec 1 (background flip) is the only breaking change and should be done as a dedicated branch. Rec 3 (hero) requires SSG work to pass featured editions to the template.

# Change Impact Effort Breaking Files
1 Load Oswald + wire heading hierarchy High Trivial No fonts.css, diablaq.css
2 Switch topbar to pure black High Trivial No diablaq.css
3 Unify brand red → #ba2d00 Medium Trivial No diablaq.css
4 Cover images: remove border-radius, add 1px black border High Trivial No diablaq.css
5 Narrow container to 960px Medium Trivial No diablaq.css
6 Card title typography — smaller, bolder, denser Medium Trivial No (but depends on #7) diablaq.css
7 Add sticky category sub-nav below hero High Low No base.html, diablaq.css
8 Build full-bleed hero carousel High Medium No home.html, builder.py, diablaq.css
9 Flip content background to light (#f8f5f0) High Medium Yes diablaq.css — audit all text/placeholder colours
Sprint 1 — "CSS only" (1 day)

Do recs 1–6 above as a single CSS commit. No template changes, no Python changes. Visual transformation is immediate — black nav, hard cover borders, Oswald headings, unified red, tighter container. This is the minimum viable alignment.
Sprint 2 — "Structural" (1–2 days)

Add the sticky category sub-nav (template + CSS). Build the hero — mark 3–5 editions as featured: true, pass them from the builder, render the carousel. Finally, evaluate the background flip — the most impactful but also requires re-checking all placeholders, muted text, and dark sections.
One honest caveat: Dark Horse operates on white. If Diablaq's brand identity is fundamentally dark/nocturnal (the name means "devil/imp", the tagline is "hellishly good comics"), a full background flip may feel like a betrayal of the brand voice. The alternative is a selective light-mode: keep the body dark but give each content section a white or near-white panel background, exactly as DH does for its #content .container. The covers still pop, but the overall page retains its dark energy. This is worth a deliberate design decision, not a default.
