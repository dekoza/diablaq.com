01 Executive Summary

The current diablaq.com has 106 generated pages, of which 16 are redirect shims for legacy URLs. The remaining 90 are split across 6 overlapping navigational entry points, 3 listing pages that often show the same editions, and a content corpus riddled with inconsistencies. The user who arrives on this site has no clear path from "what is this publisher?" to "let me buy something."

By the numbers

Core problems

  1. Duplicate navigation. The cat-nav bar repeats the header. Both "Nowości" and "Zapowiedzi" are separate listing pages that are often empty or show the same editions. This is not Dark Horse — DH has one flat nav: Comics | Books | Berger Books | Products | News.
  2. Content duplication inside .md files. Four projects repeat their summary verbatim as the first line of the body. One project (obietnica) uses HTML comment hacks instead of a draft: flag. Quoting is inconsistent (some titles quoted, some bare).
  3. Legacy URL baggage embedded in the builder. legacy_path + legacy_landing generate 16 extra pages. This should be a _redirects file, not rendered HTML.
  4. CSS specificity war. 28 !important declarations because Pico CSS fights with custom styles. Solution: drop Pico, own the entire stylesheet.
  5. No discoverability infrastructure. No OG tags, no sitemap, no 404 page, no structured data.

03 Navigation Changes Explained

1. Kill the cat-nav bar

The .cat-nav sticky bar duplicates links already in the header. On mobile it's a horizontal scroll strip that looks broken because it can't fit all items. Dark Horse doesn't have this. Remove it entirely — it adds zero navigation value.

Affected: templates/base.html lines 80–91, css/diablaq.css ~150 lines of .cat-nav rules

2. Flatten "Publikacje" dropdown into "Komiksy"

The current <details> dropdown under "Publikacje" hides 4 sub-lines behind a click. DH shows "Comics | Books" as top-level flat links. Diablaq's main line should surface directly as "Komiksy" (the thing people actually come for), with Dobre Licho and Mecenat as their own flat links. "Studio" appears in footer only (low traffic).

3. Merge "Nowości" + "Zapowiedzi" into homepage-only sections

Currently these are separate listing pages (/nowe/, /zapowiedzi/) with their own URLs. Problems:

  • "Nowości" is often empty if no editions released in last 6 weeks — falls back to showing newest_anytime[:8], which is the same as homepage content
  • "Zapowiedzi" is often empty with a "come back later" message
  • Two pages that could be zero-content is poor UX

Solution: Both become homepage sections (above the fold). No standalone URLs needed. The homepage becomes the discovery hub, like DH's "New Releases" section.

4. Active navigation state

Every page already passes canonical_url to templates. Compare it against nav link href in Jinja to emit aria-current="page". CSS already has .cat-nav__inner a[aria-current="page"] but header links don't use it.

5. Mobile nav cleanup

The mobile slide-out menu currently mirrors the bloated desktop nav. With the simplified structure, it becomes 6 large links — no nested <details> needed. Closer to the Penpot mockup's original intent.

05 Homepage Changes Explained

1. Hero: manual curation, not auto-generated

Current hero logic: announcements + new_editions, filtered to those with covers. This is fragile — when there are no announcements and no editions within 6 weeks, the hero is empty. When it's populated, its content duplicates the "Nowości" section below it.

Proposed: Add a featured: true YAML flag to edition frontmatter. Builder picks the first featured edition for the hero. This gives editorial control — the publisher decides what to promote, not an algorithm.

2. Kill separate listing pages

Remove /nowe/ and /zapowiedzi/ as standalone pages. Their content is always a subset of what's on the homepage. Fewer pages = fewer dead ends, cleaner sitemap, no confusion about which page to bookmark.

3. Full catalog on homepage

Currently only 4 projects appear in "Katalog". With 18 projects, this means 14 are invisible from the homepage. DH shows all their series upfront. The proposed homepage groups projects by line (Komiksy, Dobre Licho, Mecenat, Studio) with section headers — one scrollable page that answers "what does this publisher make?"

4. Newsletter: fix or remove

The newsletter CTA currently links to #. A dead button is worse than no button. Either wire it to a real MailerLite/Brevo form URL, or remove it entirely until one exists. Proposed: move it to footer (less prominent, doesn't waste prime real estate), and only show when a real URL is configured in builder config.

5. No redundant sections

Currently: hero shows editions A → "Zapowiedzi" shows editions B (subset of A) → "Nowości" shows editions A again → "Katalog" shows 4 projects. The user scrolls past 3 renderings of the same data. Proposed: each section has unique content. Hero = 1 featured item. Nowości = latest 8 by date. Zapowiedzi = future-dated only, hidden when empty. Catalog = all projects.

07 Catalog Changes Explained

1. Consolidate 4 section pages into 1

Currently the builder generates 4 separate pages via _write_section(). Each has identical markup with different filtered project lists. This splits a tiny catalog (18 projects total) across 4 URLs. Nobody bookmarks /mecenat/ — it has 1 project (BZIK).

Proposed: Single /komiksy/ page with <section> elements for each line, each with an id anchor. Header link "Dobre Licho" can link to /komiksy/#dobre-licho if we want direct access, though the flat nav proposal puts it as a top-level link to its own section anchor.

2. Group by line with visual hierarchy

DH's catalog page groups content into clear categories (Comics, Books, etc.) with headers. The proposed page mirrors this: Główna linia → Dobre Licho → Mecenat → Studio, each with a section header. This lets the user scroll through the entire catalog in one view — much faster than clicking through 4 pages.

3. Keep sub-line URLs as redirects only

For backward compatibility (and if someone types /dobre-licho/), emit a _redirects entry pointing to /komiksy/#dobre-licho. No HTML shim pages needed.

4. Project cards: show all, not first 4

The current homepage projects[:4] slice is arbitrary. The catalog page shows all. With the unified layout, users discover the full catalog without separate section-hunting.

09 Project Page Changes Explained

1. Deduplicate summary → body

Four projects (ciekawscy, czlowiek-ciec, kodiak, spolka-zlo) have summary that repeats verbatim in the body. Fix: keep the summary for cards/listings, make the body either empty or contain actually different long-form text. The template should render html_body only when it's non-empty AND differs from summary.

2. Add breadcrumb navigation

DH shows "Comics › Series Name" at the top of every series page. This gives context and a one-click path back to the catalog. Current site has a standalone h1 with no breadcrumb. Simple change: render line → project.title as a breadcrumb.

3. Cover + text side-by-side layout

Current project page shows h1 + summary stacked, then "O komiksie" as a separate section. DH-style: cover image on the left, text on the right. Same data, better presentation. This is a template-only change — the model already has cover_image and html_body.

4. Eliminate legacy_landing full-page duplicates

When legacy_landing: true, the builder renders the FULL project page at both /publikacje/kodiak/ and /kodiak/. This means Google indexes the same content at two URLs, cannibalizing SEO. Fix: replace with a _redirects entry. The canonical URL is the only rendered page.

5. Remove "O komiksie" section header

This section header appears even when the body is one sentence. It adds a false sense of depth. On DH, the description is just part of the page layout — no separate section. Remove the header; let the text flow naturally.

11 Edition Page Changes Explained

1. Fix the buy_links bug

In _partials/edition_details.html, the template checks {% if buy_links %} but the variable is actually v.buy_links (on the variant object). The condition is always false. This means buy links never render for single-variant editions. This is a showstopper bug for a publisher website.

File: templates/_partials/edition_details.html — two occurrences of {% if buy_links %}

2. Breadcrumb instead of back-link

The current back-link (← Kodiak) is ambiguous — it could mean "go to project" or "go back in history." A proper breadcrumb (Komiksy › Kodiak › #01) gives structural context and is crawlable for SEO (schema.org BreadcrumbList).

3. Jednotomówki: don't embed edition inside project page

Currently, when a project has exactly 1 edition, the edition details render inline on the project page. This creates a hybrid page that's harder to link to, harder to share, and harder to crawl. Proposed: every edition gets its own page. The project page shows a project card + a link to the edition. Consistent, predictable.

4. Prominent buy CTA

DH makes the "Add to Cart" button the most visible element on the page. Currently, buy links are buried under specs in a <dl> definition list. Proposed: primary CTA button above the fold, next to the cover image. Even with external shop links (strefakomiksu.pl), the action should be obvious.

5. Specs consolidation

For editions with a single variant, specs are currently shown under "Parametry" without ISBN. For multi-variant editions, each variant gets its own <dl>. Proposed: always show ISBN (it's data that exists), always show variant binding/version label. No hidden data.

13 Content Cleanup Explained

1. Add draft: true support to builder

The obietnica project uses an HTML comment hack to disable itself. The correct approach is a draft: true frontmatter flag. The builder should skip projects and editions with draft: true. This is a 3-line change in parsing.py.

2. Enforce summary ≠ body

Add a validation step: if summary text appears as a prefix of the body, emit a warning at build time. The fix is editorial: rewrite the body to provide additional depth, or leave it empty (let the summary speak for itself).

3. Normalize all YAML quoting

Pick a convention and enforce it. Recommendation: quote all string values in frontmatter. This prevents YAML parsing surprises with special characters (e.g., the ™ in "MidGuard™" or the , in "PAAtrzcie, co oni robią!"). Use a pre-commit hook or a build-time linter.

4. Require cover_image and summary

Add build-time validation: every non-draft project must have both cover_image (pointing to an existing file) and summary. Currently the builder silently accepts missing data and renders broken cards.

5. Buy links audit

23 of 35 editions have no buy links. For a publisher website, this is the equivalent of a retail store with no price tags. Every published (non-draft, non-announcement) edition should have at least one buy link. Add a build-time warning for published editions missing buy_links.

17 Builder Changes Explained

1. Drop Pico CSS

Pico is a classless CSS framework — it styles raw HTML elements. The site uses custom classes for everything. Pico's contribution is negative: it adds 45KB, forces !important overrides, and fights every layout choice. Replace with a minimal CSS reset (normalize.css or custom 50-line reset) and own the entire stylesheet.

2. Self-host fonts

Google Fonts @import in CSS creates a render-blocking request chain: browser loads fonts.css → which loads Google Fonts CSS → which loads WOFF2 files. Self-hosting (downloading the font files into fonts/) eliminates the chain and improves TTFB. Two font families × 3-4 weights = ~200KB of WOFF2 files, loaded in parallel instead of sequentially.

3. Single CSS output file

Merge fonts.css + diablaq.css into one file during build. Optionally minify with a simple regex-based minifier (no node.js dependency needed). One file = one HTTP request = faster.

4. Simplify builder architecture

Replace callback injection pattern (_render, _write_html, _write_section) with a simple BuildContext dataclass that holds env, out_dir, site_url, nav_projects. Each render function receives the context object. Less ceremony, easier to test.

5. Add validation pass

After loading content and before rendering, run a validation pass that checks:

  • Every non-draft project has cover_image (pointing to existing file) and summary
  • Every published edition has buy_links
  • No summary text duplicated in body
  • All cover_image paths resolve to existing files

Emit warnings (not errors) so the build doesn't break, but the author gets feedback.

6. Remove mvp.css

The file css/mvp.css exists but is not loaded by any template. Delete it.
